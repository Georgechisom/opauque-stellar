# Poseidon Parameter Provenance

This document records the origin, generation method, and security rationale for every Poseidon parameter used in the Opaque circuits and the `opaque-poseidon` Rust crate.

## 2. Field Specification

| Parameter | Value |
|---|---|
| Field | BN254 scalar field |
| Prime `r` | `21888242871839275222246405745257275088548364400416034343698204186575808495617` |
| Bit size | 254 bits |
| S-box exponent α | 5 (i.e., `x^5 mod r`) |

The prime `r` is the order of the BN254 elliptic curve group. The choice of `α = 5` is the smallest integer coprime to `r − 1` that satisfies the Poseidon security requirements, ensuring the S-box is a permutation over `GF(r)`.

## 3. Round Number Specification

Round numbers follow the **circomlib v2.0.5** Poseidon instantiation, which implements the parameters from the reference paper (see §5 below).

| t (state width) | N\_ROUNDS\_F (full) | N\_ROUNDS\_P (partial) | Total rounds |
|---|---|---|---|
| 2 | 8 | 57 | 65 |
| 3 | 8 | 57 | 65 |
| 4 | 8 | 56 | 64 |
| 5 | 8 | 60 | 68 |
| 6 | 8 | 60 | 68 |

`N_ROUNDS_F` is split evenly: 4 full rounds precede the partial rounds and 4 follow them.

These values are verified in `contracts/opaque-poseidon/src/constants.rs`:

```rust
pub const N_ROUNDS_F: usize = 8;
pub const N_ROUNDS_P_T3: usize = 57;   // t = 3 (arity 2)
pub const N_ROUNDS_P_T4: usize = 56;   // t = 4 (arity 3)
```

## 4. Round Constants and MDS Matrix

### 4.1 Round Constants (C)

Round constants are generated by a **Grain LFSR** seeded with the tuple `(p, α, m, R_F, R_P)` where:

- `p` = field prime `r`
- `α` = 5
- `m` = t (state width)
- `R_F` = `N_ROUNDS_F`
- `R_P` = `N_ROUNDS_P`

The LFSR produces a pseudorandom bit stream; field elements are sampled by taking 256-bit windows and reducing modulo `r` (skipping rejections that land outside the field). This is the same procedure used in the original Poseidon reference implementation by the paper authors.

### 4.2 MDS Matrix (M)

The MDS matrix is constructed as a **Cauchy matrix** over `GF(r)` with entries:

```
M[i][j] = 1 / (x_i - y_j)    for  x_i ≠ y_j
```

where `x_0, …, x_{t-1}` and `y_0, …, y_{t-1}` are distinct field elements drawn from the Grain LFSR output after the round constants. A Cauchy matrix with distinct `x` and `y` is guaranteed to be MDS (every square sub-matrix is invertible), satisfying the Poseidon security requirement for maximal branch number.

### 4.3 Machine-Generated Constants in This Repository

The constants in `contracts/opaque-poseidon/src/constants.rs` are **pre-converted to Montgomery form** (`c · R mod r`, where `R = 2^256`) for efficient in-circuit and Rust field arithmetic. They were generated by:

```
tsx contracts/opaque-poseidon/scripts/gen-poseidon-constants.ts
```

which imports the same parameters from `circomlibjs` (the JavaScript reference implementation) and emits them as Rust `Fr` Montgomery-form constants. The `DO NOT EDIT BY HAND` header in `constants.rs` enforces that constants are always regenerated from the canonical source, not manually overridden.

**To verify consistency:** run `cargo test` in `contracts/opaque-poseidon/`. The test suite includes known-answer vectors from `circomlibjs` (e.g., `Poseidon([1, 2])`) and fails if the Rust output diverges by even one bit.

## 6. Security Rationale

The Poseidon paper proves lower bounds against the following attack families for the chosen round counts:

| Attack | Condition |
|---|---|
| Statistical (differential / linear) | `R_F ≥ 6` for statistical full-round security |
| Interpolation (Lagrange) | `R_F + R_P ≥ log_α(p) + 2` |
| Gröbner basis (algebraic) | `2 · R_F + R_P ≥ min(…)` (see paper §5.2) |
| Subfield attack | No subfield of characteristic `r` for a prime field; N/A |

For BN254 (254-bit prime, α=5):

- `log_5(r) ≈ 109.5`
- Interpolation lower bound ≈ 112 rounds (total)
- Chosen `R_F + R_P ≥ 64` for all arity values used here; with a **security margin of ≥ 2× the minimum** to absorb future cryptanalytic advances

The parameter choices are taken directly from the paper's recommended table for 128-bit security, with no modification.

---

## 7. Absence of Custom Parameters

This project does **not** define any Poseidon parameters beyond those specified by circomlib v2.0.5. Any future arity or field change must:

1. Re-derive round constants and MDS via the Grain LFSR with the new `(p, α, m, R_F, R_P)` tuple.
2. Regenerate `constants.rs` via `gen-poseidon-constants.ts`.
3. Verify against the paper's round count tables for 128-bit security.
4. Add new known-answer vectors to `contracts/opaque-poseidon/src/lib.rs`.
5. Update this document.
